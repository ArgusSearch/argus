# Counterfactual replay

Argus can replay a supported MockMart incident with the named fault switched off.
Plot the two hourly curves together to show when they separated and how much of the gap disappeared.

## HTTP contract

`GET /incidents/{id}/counterfactual` serves the incident on the current live or recorded stream.
It takes no query parameters and returns JSON.
The route appears in the FastAPI OpenAPI schema at `GET /openapi.json`.

| Status | Meaning |
| --- | --- |
| `200` | Replay proof and chart data |
| `404` | The incident has not appeared on this stream or does not exist |
| `409` | No supported intervention or factual receipt, missing replay configuration, or failure to reproduce the observation |

Error bodies use FastAPI's `{"detail": "…"}` shape.
Each request regenerates two worlds and can take a few seconds.
During a run, fetch after an incident is supported and refresh as new data hours arrive.

### Example response

S4 with seed 7 after the full first day is visible, with two points shown from each series.
The actual response contains all 30 hourly points in this window.
The complete [saved receipt](../../tests/counterfactual/fixtures/s4_receipt.json) contains the SQL strings.

```json
{
  "factual_series": [
    { "hour": "2026-11-20T00:00:00", "value": 3.016, "expected": 1.0 },
    { "hour": "2026-11-20T16:00:00", "value": 0.378, "expected": 1.0 }
  ],
  "counterfactual_series": [
    { "hour": "2026-11-20T00:00:00", "value": 1.007, "expected": 1.0 },
    { "hour": "2026-11-20T16:00:00", "value": 0.955, "expected": 1.0 }
  ],
  "explained_share": 0.982,
  "gap": { "factual": 26.946, "counterfactual": 0.486, "removed": 26.461 },
  "receipt": {
    "plan": {
      "version": "mockmart-paired-v1",
      "scenario": "s4",
      "config": { "seed": 7, "days": 42, "live_days": 5 },
      "intervention": {
        "log": "log_deploys",
        "ref": "dep_ad-pacer_1.7.0",
        "ts": "2026-11-19T23:29:00",
        "kind": "deploy",
        "description": "ad-pacer 1.7.0 rolled out for the DE and FR budget lines (faster intraday pacing)",
        "scope": { "country": ["DE", "FR"] }
      },
      "metric": "pacing_ratio",
      "segment": {},
      "onset": "2026-11-20T00:00:00",
      "window": { "start": "2026-11-19T18:00:00", "end": "2026-11-20T23:00:00" },
      "as_of": "2026-11-21T01:00:00"
    },
    "factual": { "sql": "<compiled query>", "result_hash": "sha256:5a85068e6504a605", "rows": 30 },
    "counterfactual": { "sql": "<compiled query>", "result_hash": "sha256:aa46489da7e619cb", "rows": 30 }
  }
}
```

- Both arrays contain the same ascending `hour` values and a shared `expected` value for each hour.
  Timestamps are MockMart's timezone-naive simulation time.
- `receipt.plan.metric` is `payment_success_rate` or `pacing_ratio`.
  Values are fractions, so `0.95` is 95% payment success and `1.0` is delivery exactly on plan.
  `receipt.plan.segment` is the measured slice, with `{}` denoting the whole business.
  `receipt.plan.intervention.scope` identifies where the named event applied.
- The window includes six pre-onset hours and up to 12 post-onset hours for S1 or 24 for S4, counting the onset hour.
  The clock caps the window at the last complete data hour using the two-hour delivery lag.
- Each gap sums absolute hourly deviations from `expected` starting at `onset`.
  S1 pools payment successes and attempts from the same hour of the previous four weeks.
  S4 uses the planned spend ratio of 1.
  `removed` is the factual gap minus the counterfactual gap and can be negative.
  `explained_share` is `max(0, removed / factual)`, in the range 0 to 1.
- The receipt pins the world configuration, intervention, metric, slice, window, clock and both SQL result hashes.
  S1's factual SQL result includes the four weeks of comparison rows used to calculate the expectation.

## Try it and verify

```sh
uv run argus counterfactual --scenario s4
uv run argus counterfactual --scenario s1 --seed 7
uv run argus counterfactual --receipt tests/counterfactual/fixtures/s4_receipt.json
```

Pass a receipt object or the complete HTTP response to `--receipt`.
The CLI reconstructs both queries from the replay plan and exits with an error if the result hashes or SQL differ from the saved receipt.
It accepts `--receipt -` to read JSON from stdin.

```sh
make api SCENARIO=s4
# In another terminal, advance the recording and verify its incident.
curl -fsS -X POST -H 'Content-Type: application/json' -d '{"action":"end"}' http://127.0.0.1:8000/replay
curl -fsS http://127.0.0.1:8000/incidents/INC-0001/counterfactual | uv run argus counterfactual --receipt -
```

The bundled S1 and S4 recordings use seed 1.
Live worlds generated by `make demo` carry the seed in the directory name, such as `runs/s4-7`.
For custom paths or recordings, set `ARGUS_COUNTERFACTUAL_SEED` when starting the API.
The API checks the regenerated event time and the incident's original root SQL receipt before returning proof.
[Demo playback](demo.md) links the same proof from its verdict beat at `GET /demo/counterfactual`, for the demo's own S1 or S4 recording.
Python callers can use `from argus.counterfactual import counterfactual`.
`counterfactual(incident)` uses the bundled recording seed and checks the named event.
For other worlds, pass `config`, a simulation `as_of`, and the root `reference` receipt if available.

## What the simulator proves

S1 toggles the PayCo success-probability shock while the Android release is an inert log entry.
S4 toggles the DE and FR pacing override while retaining the original budget plan.
These scenarios each contain one injected metric change, so the extension uses MockMart's existing `quiet` generator as their off state.
Both runs use the same seed, calendar and background parameters.
The off world omits scenario-specific log rows and can draw slightly different realized noise because changing a distribution can advance the sampling stream differently.
The chart measures recovery relative to a separate expectation, so sampling noise can leave a residual gap.
The claim is conditional on the simulator and its interventions.

S2's planned change is expected, S3 is a delivery issue, and the quiet run has no fault.
S5's incident is a checkout-routing configuration change, for which MockMart has no paired off-world, so its route returns HTTP 409.
These cases have no counterfactual proof.
The replay uses local simulator subprocesses and SQL and makes zero LLM or external API calls.

The shared hooks are the additive CLI subcommand registration in `src/argus/cli.py` and the router registration in `src/argus/api/app.py`.
